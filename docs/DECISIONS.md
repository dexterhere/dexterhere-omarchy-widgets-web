- 2026-10-17 CI-GATE (security hook) The maintainer gate no longer reads a list from the PR working tree. CODEOWNERS covers `/scripts/` and `/.github/`, but with a single maintainer GitHub cannot require a second approval, so the real control is the maintainer reading every PR that touches those paths. Would change with a second maintainer (require code-owner review) or by running the gate from the base branch in a `pull_request_target` workflow (not done: it has its own risks).

- 2026-10-17 REGISTRY-AUTHOR-BINDING (security review) `scripts/check-review-changes.ts` now also binds listings to their author. For every added or modified `registry/widgets/<id>.json` in a pull request, the namespace owner is read from the file content at the PR head (`git show HEAD:<path>`, parsed defensively) and the file name; the PR author must equal the `io.github.<owner>` owner (case-insensitive) or be a maintainer on the base branch. Other namespaces need a maintainer. Deletions are judged by the file name (owner or maintainer). A commit-only change counts as a modification. Unreadable, malformed or id-less content, or a missing author, fails closed. The decision is a pure function with injected inputs. Reason: anyone could add a listing for `io.github.<victim>` from their own PR. Same known limit as CI-GATE (the script comes from the PR head; maintainer review of `scripts/` and `.github/` is the real control).
- 2026-10-17 REGISTRY-REACHABILITY (security review) raw.githubusercontent.com serves a commit SHA from any repo in a fork network, so a listing could name the victim's repo but pin a malicious fork's commit. Before fetching raw files the build asks `api.github.com` for the repo's default branch and calls `compare/<default>...<commit>`; only status `behind` or `identical` (the commit is an ancestor of the default branch) is accepted; `ahead`, `diverged`, 404 and anything else are rejected. owner, repo, branch and commit are validated with strict regexes and branch segments are URL-encoded. api.github.com joins the allow-list with the same rules as the raw host (https, no credentials or ports, `redirect: 'error'`, 10 s, size cap while streaming, JSON only, own-property reads). `GITHUB_TOKEN` is sent as a Bearer token only to api.github.com and only when set; it is never sent to the raw host nor logged. Skipped for fixtures and `--offline`; `--skip-reachability` exists for local development only and a unit test asserts `ci.yml` never uses it. Trade-off: only commits reachable from the default branch can be listed (a commit on an unmerged branch or tag-only commit is rejected; merge or fast-forward first), and a force-push that drops a listed commit makes the next build fail. Rate limits: 60 requests per hour unauthenticated, higher with the token (two requests per listing); CI passes the workflow token via `env:` on the registry step, permissions stay read-only. Would change: a registry-side mirror of reviewed commits, or signed attestations.

Authored pages are deliberately not touched (authors may embed components). The fetcher mirrors the registry's: https only, exact host, no redirects, 512 KB cap while streaming, 10 s timeout, strict ref charset.

- 2026-10-17 DOCS-ROUTES `/docs/` is a prerendered page with a meta refresh and a link to the latest version's first page; `/docs/<v>/` redirects the same way. Search uses `data-pagefind-body` plus a `version` filter, so results are per version.
- 2026-10-17 DOCS-SYNC-HARDENING (security review) Three fixes to synced content. (1) Trust in raw nodes no longer comes from their content: `highlight()` tags its own output with a per-build random nonce attribute (`data-hl`), and the synced-page pass keeps only raw nodes that carry it (nonce stripped, braces entity-escaped); every other raw node becomes escaped text, so a document containing `<pre class="shiki ...` stays inert. (2) The same pass now filters elements of synced pages: script/iframe/object/embed/form/style/svg and similar dropped; `style`, `srcset`, `on*` removed; URLs limited to http, https, mailto, relative and fragment (anything else becomes `#`, scheme check ignores control and zero-width characters); braces in URLs are double percent-encoded because mdsvex percent-decodes hrefs after plugins run, and braces in other attribute values become fullwidth braces. A hand-written sanitizer was chosen over rehype-sanitize because the shiki output (inline style, nonce) and mdsvex raw nodes do not fit a strict schema without reintroducing trust by content. (3) `escapeForMdsvex` now parses the source with micromark (`mdast-util-from-markdown`, CommonMark exact) and escapes only text and html nodes by source offset, so fence info strings, code-span run lengths, tilde and indented fences and unclosed fences follow the spec instead of a regex. It does not touch link or image attributes; the compile-time pass covers those. Tests cover each case.
- 2026-10-17 DOCS-ATTR-ENCODING (second security review) mdsvex writes attribute values into the Svelte source unescaped, so `![x" ONERROR="y](u)` produced a real attribute (and `"><meta http-equiv=refresh>` a real element); hast properties looked safe, the serialised output was not. Fix: `rehypeEncodeAttrs` runs last on ALL pages and entity-encodes `& " < > { }` in every string attribute value and array item of every markdown-derived element (Svelte decodes entities in attributes, so braces become literal characters, never expressions). Authored raw HTML is not an element at this stage and stays the author's responsibility. In URL properties literal and percent-encoded braces are double-encoded (`%257B`) because mdsvex percent-decodes hrefs after plugins run (verified: `/q/%7Bx%7D` came out as `/q/{x}`); a legitimate `%7B` in a URL therefore becomes a literal `%7B` path segment, acceptable for docs. Tests now parse the compiled Svelte output and check every element and attribute against an allow-list, with the reviewer's payloads plus a 250-case fuzz. Also: autolink headings use `append` (a `#` anchor with an aria-label) so a link inside a heading no longer nests anchors and breaks the build; protocol-relative (`//host`) and backslash URLs are rejected on synced pages; toc text decodes a fixed entity set (rendered as text only).
- 2026-10-17 DOCS-SYNC-SOURCE The sync script uses a local checkout only when `CODE_REPO_PATH` is set explicitly (the sibling `../omarchy-widgets` is no longer picked up), prints a warning naming the path and HEAD, writes `local:<sha>` provenance into the generated header instead of claiming `@ref`, and refuses symbolic links. The default is the network fetch at the pinned ref. The `version` argument is validated with the same `isVersionId` check as snapshots. The preview plugin returns `next()` on malformed percent-encoding.
- 2026-10-17 DOCS-CSP-STYLE Considered dropping `style-src 'unsafe-inline'` for docs routes: not feasible, Svelte scoped and component styles and shiki's inline `style` attributes need it, and the CSP is a single static meta tag for the whole site. Instead the defence is not letting attacker text reach a `style` attribute: synced pages drop `style` properties, raw HTML is demoted to text, and attribute values are entity-encoded so a value cannot open a new attribute. Residual risk: authored pages may contain raw HTML with `style` (maintainer-reviewed content), and `meta refresh`/same-origin script src are not covered by CSP, which is why the allow-list test exists. Revisit if styles move to external sheets.

- 2026-10-17 STATS-DESIGN Views and likes go through a `StatsProvider` (`src/lib/stats/`). Default `LocalStatsProvider`: likes are the visitor's own favourites in `localStorage` (`ow-liked`, validated against the registry id shape on every read, capped at 500, works with storage blocked via an in-memory fallback), global counts are `null` so the UI shows none, and no view is counted at all (nothing would display it). `RemoteStatsProvider` is chosen only when `PUBLIC_STATS_URL` is set at build time (validated: https, or http for localhost; bare origin, no credentials, path, query or fragment; an invalid value fails the build). It uses 3 s timeouts, a 16 KB response cap while streaming, strict JSON validation with own-property reads and safe non-negative integers, `credentials: 'omit'`, `referrerPolicy: 'no-referrer'`, `redirect: 'error'`. A failure hides counts and pauses remote calls for 60 s; likes stay local. The random 128-bit client id lives in `localStorage` (`ow-client`), is created only on the first write, and is sent only to the stats origin on writes (never on reads). Views honour `navigator.doNotTrack === '1'` and `globalPrivacyControl` (no id created, no request), are gated once per widget per UTC day in `ow-viewed`, and `StatsRow` records one only when given `view` (a widget page that was opened), never for cards.
- 2026-10-17 STATS-SERVICE `services/stats/` is a dependency-free `fetch(request, env)` handler with a `Store` interface (KV and in-memory). Unique view per (widget, UTC day, HMAC(secret, day|widget|token)), unique like per (widget, HMAC(secret, widget|token)); view rows expire after 48 h, like rows after 400 days (a like must stay revocable, so a pseudonymous row exists until unlike; per-widget HMAC stops cross-widget linking). No IP, user agent or referrer is read, stored or logged; the handler never touches `console`. Rate limits: fixed per-minute windows keyed by the HMAC of the token (30) plus one global bucket (1200). CORS is an exact-match allow-list (`*` is ignored), writes require an allowed Origin, `Vary: Origin`, uniform error bodies. DNT and Sec-GPC on a view request are acknowledged and not counted. Known limits: KV read-modify-write is not atomic (lost counts possible), tokens are free to mint so the global bucket and an edge rate rule are the real flood guard, any id with the registry shape can get a counter unless `WIDGET_IDS` is set.
- 2026-10-17 STATS-CSP `connect-src` is built by `connectSrc(PUBLIC_STATS_URL)` in `src/lib/stats/origin.ts`, unit tested: unset or invalid means `'self'` only (unchanged); valid adds exactly that origin. Nothing is enabled by default; `.env.example` documents the variable.
- 2026-10-17 STATS-DEMO The components are tested end to end on an unlinked route `/__stats-demo/` (noindex, `data-pagefind-ignore`). `scripts/prune-demo.ts` deletes it from `build/` unless `STATS_DEMO=1`, so production builds do not ship it; CI sets `STATS_DEMO=1` for its build and the e2e test skips itself when the route is absent. - 2026-10-17 STATS-HARDENING (security review) Client-chosen ids let anyone mint unlimited identities, so the service now issues the identity. `GET /challenge` returns a signed 2-minute single-use challenge; `POST /token` (headers `X-Challenge`, `X-Pow`) checks the signature, expiry, replay (`setIfAbsent`) and an 18-bit SHA-256 proof of work, then returns `v1.<random>.<expiry>.<hmac>` (30 days, constant-time check, `STATS_SECRET_PREVIOUS` for rotation). Writes need a valid token; the dedupe identity is the token's random part. The client solves the work in 8 ms slices with a yield between them. Rate limits additionally key on `HMAC(daily salt, IPv4 /24 or IPv6 /48 prefix)` from `CF-Connecting-IP`: used only as a rate-limit counter key that expires in 2 minutes, never logged, never stored with a widget or joined to a token, rotating daily; no header means one shared bucket. This changes the earlier "no IP" wording to "no IP stored or logged; a salted daily hash of the network prefix is held for minutes for rate limiting" (README, `docs/stats-privacy.md`). Storage is now atomic (`incr` with a floor of 0, `setIfAbsent`, `delete`): in-memory for tests and D1 (`schema.sql`, parameterised SQL, tested against real SQLite when `node:sqlite` exists); the non-atomic KV adapter was dropped. Residual risk, stated in the docs: counts can still be inflated at proof-of-work cost, are a popularity signal only, and must never gate anything security-relevant; without a service the UI says "Like (saved on this device)" and shows no numbers.
- 2026-10-17 CATEGORIES (D-I6) Listings carry `categories` (1 to 3 distinct slugs of the 10, schema-enforced) instead of `category`. `widget.json` keeps its single `category` because that schema is pinned from the code repo; the build requires it to be one of the listing's categories and makes it the primary: output `categories` is primary first, the rest sorted, so it never depends on listing order. `category` (the primary) is still emitted for older consumers; every site consumer now reads `categories`. A widget appears under every category it lists; `counts.byCategory` therefore sums to more than `total`. A unit test scans `registry/widgets` and fails the build if a listing has none. Would change when the code repo's widget schema moves to `categories`.
