## 4. Open decisions and human-only tasks

1. **Where to host** and the real **domain** (two names: `<domain>` and `docs.<domain>`); set `PUBLIC_SITE_ORIGIN` and `PUBLIC_DOCS_ORIGIN`.
2. **Global likes and views**: deploy the stats service, or keep likes local-only. The service stores no IPs or user agents, but it holds a short-lived salted hash of the network prefix for rate limiting; the Security page must say so.
3. **Release signing key**: the code repo `PKGBUILD` refuses to build until you pin a key fingerprint.
4. **Name and branding**: "Omarchy Widgets" is a placeholder; using the Omarchy name or look is a question for the Omarchy maintainers. Contacting the `anishfn/omarchy-widgets` maintainer is yours.
5. **Chord**: our proposed Widget Center chord is `Super + Alt + W`. Omarchy's own defaults use `Super + Shift + W` (Writing) and `Super + Ctrl + W` (network panel). Verify on a real Omarchy 4 install (code-repo spike S13) and update the code repo's decision D-7 and `design/`.
6. **GSAP licence**: free "no charge" licence, not OSI open source; recorded in `docs/DECISIONS.md`.
7. Turn on **GitHub Discussions** if you want a Community link in the footer.
8. Allow-listing `GITHUB_TOKEN` for the registry build step in CI is intentionally not done (an existing test requires the token on the registry step only); the reachability check works unauthenticated within rate limits.

## 5. Run and verify locally

```bash
cd omarchy-widgets-web
git switch develop && git pull
bun install --frozen-lockfile
PORT=4300 bun run build:hosts      # build for the two hostnames
PORT=4300 bun run serve:local      # site: http://localhost:4300/  docs: http://docs.localhost:4300/
bun run check && bun run lint && bun run themes:check && bun run registry
bunx vitest run && bun run build && PW_PORT=4301 bun run test:e2e
```

Stop the server with `fuser -k 4300/tcp`. Do not use `pkill` patterns that can match your own shell.

## 6. Process notes worth keeping

- Every security-relevant PR got an independent review (separate agents; Codex was blocked by a content filter on adversarial wording, so Claude agents ran the code against hostile inputs instead). The automated security hook also flagged several real issues that were fixed.
- A PR with merge conflicts does not get CI at all (GitHub skips it). If CI "never starts", rebase onto `origin/develop`.
- Agent worktrees live in `.claude/worktrees/` (git-ignored). The WIP commits above are on the remote, so the worktrees can be deleted.
- Scripted multi-line edits silently missed twice in the code repo (an `umask` and a CPU baseline). Assert that the text being replaced exists, and re-verify recorded fixes with a test.
